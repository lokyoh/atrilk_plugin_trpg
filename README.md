# atrilk_plugin_trpg

ATRI-LK 的跑团插件：DND 5e 角色卡（含 0~3 环法术）+ 由 DM Agent 主持的冒险（世界按需生成、场景按本局构建、战斗与施法逐回合结算、倒地与死亡豁免、自动攒剧情复盘）。

> 本项目是 [ATRI-LK](https://github.com/lokyoh/ATRI-LK) 的插件，仅支持 OneBot 适配器。

## 指令

所有指令都挂在主指令「跑团」之下，不会占用顶层通用词。

| 指令 | 说明 | 示例 |
| --- | --- | --- |
| `/跑团.建卡` | 按步骤引导生成 DND 5e 角色卡 | `/跑团.建卡`（也可以 `/跑团.建卡 精灵` 直接带上一步回答） |
| `/跑团.看卡` | 查看已保存的角色卡 | `/跑团.看卡` |
| `/跑团.骰` | 掷骰表达式，多个用逗号分隔 | `/跑团.骰 2d6+3`、`/跑团.骰 1d20, 4d6` |
| `/跑团.检定` | 技能 / 属性 / 豁免检定 | `/跑团.检定 察觉 DC15 优势`、`/跑团.检定 力量豁免 DC20` |
| `/跑团.改卡` | 重做建卡中的一步（属性 / 种族 / 职业 / 背景 / 技能 / 装备包 / 法术） | `/跑团.改卡 种族`、`/跑团.改卡 法术`、`/跑团.改卡 职业 法师` |
| `/跑团.开局` | 准备一局冒险：选择世界与故事（或用「生成」新建，用「预设」装内置世界），建立存档并绑定本会话（**还不开局**） | `/跑团.开局`、`/跑团.开局 2`、`/跑团.开局 生成 低魔中世纪`、`/跑团.开局 预设` |
| `/跑团.加入` | 加入本会话准备中的存档（不带存档 ID 就加入当前绑定的那一局） | `/跑团.加入`、`/跑团.加入 save_20261017_ab12` |
| `/跑团.开始` | 人都到齐后正式开局（跑开场白），任意已加入的玩家都可以发 | `/跑团.开始` |
| `/跑团.继续` | 继续一局暂停中的冒险（重新绑定本会话） | `/跑团.继续`、`/跑团.继续 save_20261017_ab12` |
| `/跑团.存档` | 查看当前存档（含玩家名单、角色状态与本局用量），或列出全部存档 | `/跑团.存档` |
| `/跑团.结档` | 告诉 DM 本局可以收尾了，由 DM 在剧情里写出结局 | `/跑团.结档` |
| `/跑团.结束` | **暂停**本会话的冒险并汇报本局用量（加「删除」才删除存档） | `/跑团.结束`、`/跑团.结束 删除` |

> 场景切换**没有玩家指令**：去哪里、何时离场入场由 DM 决定，并由 DM 在叙述里交代相应的剧情。

### 建卡流程

选择模式 → roll 属性 → 种族 → 职业 → 背景（可跳过）→ 技能 → 装备包 → 选法术 → 完成。

- roll 属性：回复「roll」掷 6 组（4d6 取最高的三个），或回复「标准数组」使用 15/14/13/12/10/8，
  再按顺序回复六个值或回复「自动」自动分配。
- 选法术：**只有施法职业会出现这一步**（野蛮人 / 战士 / 武僧 / 游荡者自动跳过；
  圣武士 / 游侠 1 级没有法术位，也会跳过）。提示词按职业列出可选戏法与一环法术，
  回复序号或法术名（用逗号分隔），也可回复「自动」按列表顺序挑；
  数量按职业固定（如法师 戏法 3 + 法术 6，邪术师 戏法 2 + 法术 2）。
- 建卡过程中的会话会实时落盘到 `data/plugins/跑团/sessions/`，整条流程由磁盘驱动：
  玩家回复的消息由常驻响应器接住，不再依赖 60 秒就过期的临时交互。
  因此建卡可以慢慢来，跨小时、跨天，甚至机器人重启后都能接着走
  （重新发送 `/跑团.建卡` 也会回到当前步骤）。回复「取消」可中途放弃，
  超过一天未继续的会话会在启动时自动清理。
- 角色卡保存为 `data/plugins/跑团/cards/<user_id>.json`。
- **角色名默认用你在 lk 插件里绑定的名称**（没绑定时是「冒险者 + QQ 尾号」）；DM 的提示词与
  叙述、`/跑团.加入` 的提示、`/跑团.存档` 的玩家名单也都用这个名字。跑团内部仍按 QQ 号
  索引玩家（存档、角色卡、等待名单都按它走），换绑 lk 名称不会影响已有存档。

### 改卡

改卡就是重做建卡中的一步。回复 `/跑团.改卡` 会列出可重做的步骤；
回复 `/跑团.改卡 <步骤>` 后按提示给出新的选择即可，也可以直接带上新选择。

- 可重做：`属性`、`种族`、`职业`、`背景`、`技能`、`装备`（装备包）、`法术`。
- 示例：`/跑团.改卡 种族` 后回复「精灵」；或 `/跑团.改卡 职业 法师`。
- 改 `属性` 时先回复「roll」（或「标准数组」），掷出的候选组需要**再回复序号挑一组**，
  挑完才会重算角色卡——只掷不挑不会把旧属性当成结果存下来。
- 改完会自动重新结算角色卡并覆盖保存。
- 改职业会清掉新职业没有的技能，把装备换回新职业的默认装备，并清空法术重新选
  （法师 / 邪术师等可再 `/跑团.改卡 法术`；改成非施法职业则法术为空）。

## 冒险（DM 主持）

1. `/跑团.建卡` 建好角色卡。
2. `/跑团.开局` **准备**一局冒险（只建存档，不跑开场）。**多世界**：世界库里可以并存多个世界，每个世界里可以有多个故事。
   - 还没有任何世界时，`/跑团.开局` 直接在后台跑入场流程（生成**地图 + 第一个故事**），
     并分阶段汇报进度（① 世界地图 ② 世界起点与推力 ③ 建立存档、等人加入）；
     完成后自动建立存档并把本会话绑定到它。
   - 已有世界时，`/跑团.开局` 会**先列出可用世界**（名称 + 一句话简介）：
     · `/跑团.开局 <序号>`（或世界名）选中一个世界；
     · `/跑团.开局 生成 [主题]` 生成一个**新世界**（不给主题就随机）——不会覆盖现有世界。
   - 选中世界后，机器人列出**这个世界里的故事**（名称 + 一句话简介）：
     · `/跑团.开局 <序号>`（或故事名）用一个已有故事开局；
     · `/跑团.开局 生成 [主题]` 在这个世界里生成**新故事**开局；
     · `/跑团.开局` 重新回到世界选择。
   - 选中的世界还没有故事时，会自动为它生成第一个故事再开局。
   - 选择状态保留 10 分钟，过期后重新发送 `/跑团.开局` 即可。
   - 世界是**所有存档共享**的；每局存档记录自己引用的世界与故事。
   - 区域 / 城镇 / 自然地点 / 地下城 / 场景**不预生成**，而是在 DM 决定玩家去往某处时按需补齐。
   - 每人**每个群同时只能开一局**（自己建的那局；参与别人的局不算），要换新的一局得先把旧存档删掉。
3. 等大家加入：`/跑团.加入`（本群不带存档 ID 就加入当前这一局；还没有角色卡先 `/跑团.建卡`）。
   `/跑团.存档` 能看到已经加入的玩家名单。
4. 人齐后，由**任意已加入的玩家**发 `/跑团.开始` **正式开局**：DM 跑开场白并把大家带进第一个场景。
   开局之前 @ 机器人不会触发 DM。
5. 直接 **@ 机器人** 描述角色的行动（如「我观察四周」）。行动**按轮推进**：
   规则判断器先把关（不符合规则会打回、信息不足会追问），通过后先把这条行动记进
   **本轮**，然后**立刻**由 DM 只结算这名玩家的行动（逐人结算：只写他这一行动的结果与影响，
   不总结全场），并在后面提示还在等谁；等这一轮**等待名单**（由 DM 用 `await_players` 决定，
   开局默认全员）上的玩家**都**提交后，DM 再输出一条**整轮总结**（把这一轮串起来、交代局势变化）。
   - 在整轮总结之前，玩家可以再 @我 **覆盖自己这一轮的行动**（会重新结算他这一次）。
   - **每轮等谁由 DM 决定**（可以只等在场的玩家），倒地 / 阵亡的玩家会被自动跳过，
     所以不会因为某个玩家不发言而卡住。
   - 倒地 / 阵亡的玩家**不能真的行动**：他的提交会被系统标注成「呓语 / 遗言」一起交给 DM
     （见下方「倒地与死亡豁免」），全队倒下时剧情也不会卡死。
   - 单人游戏只有你一个玩家，提交后直接就是整轮结果。
   - **逐人结算可以关**（见「插件设置」）：关掉后回到「全员提交 → DM 一次性主持」，
     每轮从 n 次模型调用降回 1 次；人少时（默认 <3 人）也自动走这条省成本的路。
   - DM 需要时自行调用掷骰 / 检定 / 查规则 / 查数据 / 改卡等功能；逐人结算时只为当前这名玩家结算，
     整轮总结时用 `player` 指明为谁改卡 / 检定。
   - **鉴定与攻击的骰点由系统单独回显**：叙述后面会附一段「🎲 判定」，写明谁做了什么检定、
     掷了多少、对抗多少、成功与否。DM 用 `secret_roll` 掷的**暗骰**不会出现在这里
     （那是它决定 NPC 行动与隐藏事态用的）。
   - **战斗**（DM 用 `start_combat` 开战后）改由**先攻顺序**驱动：轮到的玩家提交后立刻结算，
     该回合结束后系统把等待名单推进到下一名玩家，中间夹着的敌人回合交给 DM 用
     `enemy_attack` 结算；命中 / 伤害 / 扣血由系统掷，不靠 DM 手算。
   - 建卡续接（回复建卡问题）优先于 DM，不会互相打断。
6. **场景切换完全由 DM 决定**，玩家不能自行切换。玩家提出想去某处时，DM 会用
   `move_scene` 按需生成该地点的**通用场景**，再结合本局剧情用**场景构建器**改造成
   **本局专属场景**存进存档；DM 必须在叙述里先交代**离场**、再描述**入场**，使移动合理。
   场景被玩坏（门被砸开、NPC 死亡等）时，DM 用 `update_scene` 把变化追加到场景副本文末；
   只是「进 / 出这个场景」不记录——那类流水不影响下次读取，只会把场景文档写脏。
   提示词里只放**场景简介**（名称、一句话定位、氛围、最近变化），布局 / 在场者 / 隐藏信息
   由 DM 用 `get_scene` 按需查完整副本。
7. **本局什么时候结束由玩家决定**：发送 `/跑团.结档` 之后 DM 才会把剧情推向收束、
   写出结局并收官（收官后自动解除本会话的绑定，存档与复盘都保留）。
   玩家没表态时 DM **不能**自行结束故事，最多提醒一句「想收尾可以 /跑团.结档」。
   「结档状态」这一段**只在真的要收尾时才注入提示词**（玩家发过 `/跑团.结档`，或全队阵亡），
   平时整段不出现，省 token。
   `/跑团.结束` 则是**暂停**：立刻停手（不写结局），存档原样保留，
   并把这局的**用量汇报**（模型调用次数、token、约合花费）发给你；
   想接着玩发 `/跑团.继续`，想彻底丢掉存档用 `/跑团.结束 删除`。
   暂停后本会话的 @ 不会触发 DM，避免误触；`/跑团.继续` 会重新绑定并接着上次的场景。
   想换回别的存档用 `/跑团.继续 <存档ID>`，当前这一局会自动转为暂停状态。
8. `/跑团.存档` 查看存档（玩家名单、自己的角色状态、这一局到目前为止的用量）。

### 世界地图怎么生成（程序定地理，模型填内容）

早期做法是让模型「一边编故事一边编地图」，再正则解析它自己写的相邻关系 JSON——于是常出现
链状走廊、孤立地区、A 说和 B 相邻但 B 不认，解析失败时地区名还会退化成 JSON 的键名。
现在把**地理**交给程序（`core/dnd/world_topology.py`，纯本地、不调用模型）：

- 在网格上最远点采样撒种子，多源 BFS 把格子划给最近的种子 → **每块地都是连续的一整片**，不会出现飞地；
- 邻接 = 共享一条边的两块地 → **天然对称、平面、没有孤立点**，也不会"隔海相邻"；
- 顺带算出方位（东北 / 中……）、角色（枢纽 / 普通 / 边陲）与格数，一并写进给模型的「地区布局」；
- 同一 `seed` 可复现同一张图（`render()` 能把拓扑打印成 ASCII 图，方便排查）。

模型只负责**起名与写设定**，且必须按布局给的顺序和邻接写；正文末尾再给一段 JSON 索引
（`{"world_name": …, "intro": …, "regions": [...]}`）作为解析依据，JSON 缺失时才退回「## 地区一：名」小标题。
生成后跑一次自检（`lint_world`）：名字数量、重名、邻接有没有写进正文——**只记录警告，不自动重试**
（为一个错再生成整个世界太贵），警告会进日志与 `WorldMapResult.warnings`。

### 内置预设世界（零模型调用）

`presets/default_world/` 里放着一整套写好的内容：世界地图（灰烬海，6 个地区）、起始区域（白港）、
3 个开局场景（盐仓码头 / 灰烬台圣灰广场 / 霜牙岭哨站）、3 条故事线（灰票之冬 / 净灰之路 / 草枯之盟）。

- `/跑团.开局 预设` 把它们装进世界库（**不调用模型**，秒装），之后再 `/跑团.开局` 就能在世界列表里选；
- 装的是**文档**不是存档：预设目录与世界库里的一个世界目录**完全同构**
  （`index.json` + `docs/<kind>/<key>.md`），安装就是按索引把文档原样重放——走的和生成 agent
  落库时同一条代码路径，所以装完的世界与「现生成」的没有任何区别，`ensure_scene` 会直接命中预设场景；
- 改预设：直接编辑 `presets/default_world/` 下的文件，改完重新 `/跑团.开局 预设` 覆盖即可
  （索引里写了的文档，磁盘上就必须有对应文件，缺文件会直接报错，不会装出半个世界）；
- 反过来也一样：把 `data/plugins/跑团/world/worlds/<某个世界>/` 整个目录拷进 `presets/`，
  就是一份新预设——格式零转换。

### 世界圣经（命名与事实的唯一来源）

世界地图、故事、区域、场景是**不同的模型调用**生成的，DM 主持又是另一些调用——
各写各的，同一个人很容易在这份文档里叫「商承弼」、那份里叫「沈万三」。
世界圣经（`core/dnd/world_bible.py`，落盘 `worlds/<key>/bible.json`）就是为此存在的锚点：

- **实体登记**：人物 / 势力 / 地名 / 物品各记一条（规范名、别名、所属地区、一句话备注、出处），
  按 `(名字, 种类)` 去重合并，先来者是正史；
- **能不调用模型就不调用**：地区表、「」地标、国都 / 特殊地区小节、故事的势力 / 关键节点小标题、
  场景的在场者小标题，全部由**程序**从已落库的文档里提取；模型只在生成世界 / 故事时
  顺手在末尾 JSON 里带上程序提不出来的人物与势力；
- **消费**：`bible_text()` 生成一块有字数上限的紧凑文本，注入 DM 每轮提示词与按需生成
  （区域 / 城镇 / 地点 / 地下城 / 场景）的输入——命名与事实以它为准，需要新造名字时避开已登记的；
- **预设同样有**：`/跑团.开局 预设` 装完即播种圣经（世界 JSON 里手写的人物 / 势力 +
  故事与场景的程序提取），开局就能用；
- 字数上限在插件设置里调（`world_bible_max_chars`，默认 800，超限从尾部丢实体——
  圣经每轮都要重发，宁缺毋滥）。

### 用量与花费（计费）

每次模型调用都会把 token 用量记到**当次这一局**的存档上（`progress.billing`，按模型分项累计）：

- 覆盖 DM 主持、场景构建、按需生成地点 / 场景、开局生成世界与开场白等**所有**跑团相关调用；
- 花费按 `data/config/system/provider.yml`（WebUI 的模型配置）里给模型填的单价
  （每百万 token）换算，与 WebUI 用量统计口径一致；
  没配单价的模型只统计 token，并在汇报里注明「这部分费用未计入」；
- 用量是边跑边记的：DM 的功能调用（改卡 / 切场景 / 按需生成）各用自己的存档副本，
  之后还会整份写回 `save.json`，所以落盘前会把内存里最新的累计并回去，避免刚记上的
  用量被旧对象覆盖；
- 汇报点：`/跑团.结束`（暂停时）、`/跑团.结档` 收官那一轮、`/跑团.存档` 详情；
- 换算出的是**估算值**，实际计费以模型服务商账单为准。

### 插件设置（省模型成本）

WebUI「插件设置 → 跑团」里可以调（`config.py` 的 `TrpgConfig`，改完即时生效）：

| 设置 | 默认 | 作用 |
|---|---|---|
| 逐人结算 | 开 | 关掉后回到「全员提交 → 一次性主持」，每轮调用次数从 n 次降回 1 次 |
| 逐人结算最少人数 | 3 | 玩家人数不足就自动走一次性主持（2 人局最省），填 99 等于彻底关闭 |
| 最近事件条数 | 5 | 每轮塞给 DM 的历史条数，逐人结算时再自动减半，单条超过 160 字截断 |
| NPC 名单条数 | 6 | 提示词里最多列几名具名 NPC |
| 每轮附战场地图 | 关 | 关着时只在**站位或地形变化**的那一轮重画地图，其余轮只给坐标与距离 |
| 世界圣经字数 | 800 | 每轮塞给 DM 与按需生成的专有名词登记块上限，超限从尾部丢实体 |

另外这些是写死在代码里的省法，不需要设置：剧情 / 战斗各只下发该用的功能子集
（剧情 16 个、战斗 18 个，而不是全部 22 个）、功能说明每条压成一行（参数用
`名（类型）=说明` 串起来，比原来的多行缩进省三分之一）、多人局里非焦点玩家的角色卡压缩成一行、
「结档状态」只在收尾时注入、工具返回超过 600 字截断（`get_scene` / `start_combat` 等少数功能放宽）、
单轮思考上限 8 步、叙述篇幅硬指标（整轮 250 字 / 逐人 150 字 / 战斗 200 字，且每轮只推进
一个动作或一个信息点、选项每条 15 字以内）。

### 复盘（story.md）

每局冒险都会自动攒一份**给人看**的剧情流水：`saves/<存档ID>/story.md`。

- **只在整轮总结时写**（逐人结算的即时结果、玩家提交行动时都不写），每条记下本轮**玩家输入**、
  **系统裁定摘要**（检定 / 攻击 / 法术位等工具输出）与 **DM 的整轮叙述**；
  叙述结尾给玩家看的「接下来你们可以：」提示不会写进来；
- 标题按场景分节：`## 场景：后巷`；场景里打起来时在场景内降一级
  `### 战斗：后巷伏击`，战斗打完回到场景级继续写；
- 单卷超过 **10 MiB** 自动滚到下一卷（`story-2.md`、`story-3.md`…），
  新卷会补上卷号、承上卷与当前场景标题，单独打开任何一卷都能读懂；
- 结档时在文末落一条 `**🏁 本局就此结档。**`；
- 它和 `events.jsonl` 是两回事：后者是喂给 DM 的 history，前者是留给玩家的流水。

### 战斗（逐回合）

DM 认为该动手时用 `start_combat` 列出敌人，系统会：

- 从**怪物数据表**（CR 0~10，按中文名 / 英文名 / 别名取）取敌人的 AC、生命骰、攻击与特性，
  与玩家的先攻一起掷出**先攻顺序**，落盘到 `combat.json`；
- 剧情里的角色（商人、卫兵队长、帮派头目……）写成 **`名字:档位`** 即可参战，
  档位为 `平民` / `士兵` / `老兵` / `首领`（`打手x2:士兵` 也行），数值按**队伍等级**现算
  （档位不是图鉴条目，没有正式 CR，经验另按档位表给）；
  也可以让 NPC 直接用怪物模板（`卡尔:匪帮首领`）。**具名 NPC 会留档**到 `npcs.json`：
  带着旧伤、状态、关系与最后出现的地点，下次遇到时沿用而不是满血重生；
  单次遭遇里的杂兵（`士兵x2`）不留档；
- 把本轮的等待名单换成「当前该行动的玩家」，**只有他能提交**（别人会被挡回并看到当前顺序），
  提交即主持；该回合结束后系统推进到下一名玩家，中间夹着的敌人回合写进下一次给 DM 的
  战斗块，由 DM 用 `enemy_attack` 结算（一个敌人一轮打几次就调几次）；
- **同时生成战场棋盘**（`combat.json` 的 `width/height/tiles` + 每个参战者的 `x/y`）：
  按敌人数量定边长（9~19 格）、按场景类型选地形模板（石街窄巷 / 室内厅堂 / 林地 / 洞窟 /
  水岸 / 旷野），双方隔开 15~25 尺列阵，随机铺障碍、半掩体、四分之三掩体、困难地形、
  危险地形与浅水。**不额外调用模型**，DM 可以用 `update_battlefield` 微调单格地形；
  地图默认**只在布局变化时**重画（每轮都发一份很贵），其余轮只给尺寸、坐标与距离；
- **距离是硬的**：每格 5 尺、斜向同算 5 尺；`attack` / `cast_spell` / `enemy_attack` 结算前
  都校验射程（近战触及、武器射程、法术射程文字解析）与视线，够不着会被系统打回并告诉你
  还差多少尺；远程攻击超出**常规射程**自动带劣势；最多打到最大射程为止；
- **掩体自动算 AC**：站在半掩体 +2、四分之三掩体 +5，障碍挡通行也挡视线（判定用 Bresenham
  连线近似）；`move` 用 Dijkstra 算路径与消耗（困难地形 / 浅水一格算两格），
  每回合按**速度**（种族速度）扣预算，超了就等下一回合；
- 玩家攻击用 `attack`（按角色卡里的武器算攻击加值、命中后掷伤害并扣敌人生命，
  也可指定武器 / 优势 / 劣势）；施法用 `cast_spell`；要挪位置用 `move`；
  陷阱、环境伤害、敌人逃跑 / 投降 / 被擒等不走攻击判定的改动用 `update_enemy`；
  给具名 NPC 改状态 / 关系用 `update_npc`；
- 敌人全部退场时**自动结束**战斗；DM 也可以在自己的回合用 `end_combat` 收尾
  （撤退、议和……），之后回到「由 DM 指定等待名单」的普通推进。战斗未结束不能
  `move_scene`（会被系统拒绝，要先 `end_combat`）。
- 开战后给 DM 的返回里会强要求：**第一段叙述先把战场讲清楚**（地形光线、掩体与障碍、
  双方站位与距离），再写谁先动手——所以不会出现「打起来了但不知道站在哪」。

玩家的生命值一律以**角色卡副本**为准（先扣临时生命，再扣当前生命，降到 0 即倒地，见下一节），
敌人的生命与退场状态记在 `combat.json` 里，具名 NPC 的生命与状态会同步回 `npcs.json`，
跨轮不会丢。DM 可以用 `/跑团.存档`（或 `query_data` 查「怪物」/「档位」/「名单」表）随时核对数值。

### 倒地与死亡豁免

- **全队阵亡 = 本局结档**：所有玩家都死亡（各自 3 次死亡豁免失败）时，系统会自动进入收尾——
  DM 会先写一段结局并 `wrap_up`；万一它没来得及收尾（比如最后一击发生在它这次叙述里），
  系统也会兜底结档（清战斗、解绑会话、在复盘末尾落一条「全员阵亡，本局就此结档」），
  玩家再 @ 也不会继续这一局，想重来用 `/跑团.开局`。
- 玩家生命值降到 **0 就是倒地濒死**：轮到他的回合时由**系统自动掷死亡豁免**（d20 无加值、DC 10）——
  ≥10 记 1 次成功、≤9 记 1 次失败，**天然 20** 直接回 1 点生命并清醒，**天然 1** 记 2 次失败；
  **3 次成功 = 伤势稳定**（仍 0 血昏迷，不再掷），**3 次失败 = 死亡**（退场；想回来得靠复活术 /
  神迹这类剧情手段，DM 用 `update_character` 的 `死亡豁免` 字段裁决：`复活` / `稳定` / `清空`）。
- 倒地期间再挨打会累计失败：普通伤害 +1、**暴击 +2**；单次伤害达到或超过生命上限则**当场死亡**
  （一次伤害把满血角色打到 0 且溢出超过生命上限，同样立即死亡）。敌人对倒地的玩家补刀是合法的，
  也是死亡豁免走向死亡的正常途径。
- **任何治疗**（法术、药水、医药包）都会让他立刻恢复意识、回血并**清空死亡豁免进度**；
  伤势稳定的玩家保持昏迷，等治疗或长休。
- 倒地 / 阵亡的玩家仍然可以 @我 说话，但系统会把他的提交标注成「呓语 / 遗言」交给 DM
  （DM 不会让倒地的角色真的行动），等待名单里也会自动跳过倒地 / 阵亡的人——**全队倒下时剧情也不会卡住**。
- 死亡豁免进度记在**角色卡**上（`/跑团.看卡` 的「生存状态」一行），跨战斗、跨场景都不会丢。

### 动作经济（软提示）

- 每名玩家一个回合有 1 个动作 + 1 个附赠动作 + 1 次反应 + 一次移动。战斗中系统会按 DM 调用的工具
  **自动记账**：`attack` 与「1 动作」法术记动作，附赠动作法术记附赠，反应法术记反应，
  玩家行动描述里出现移动类词就记一次移动；战斗块里显示「本回合已用：…」，进入自己的新回合时清空。
- 这只是**提示**：资源用完之后工具会多回一句提醒，但**不拦截**——同一动作的多段攻击（额外攻击）、
  借机攻击、DM 裁定允许的额外行动都可以照常叙述，最终裁决权在 DM 手里。

### 法术（0~3 环）

- 法术表共 121 个（戏法 25 / 一环 42 / 二环 29 / 三环 25），按中文名 / 英文名 / 键取用，
  `query_data` 的 `法术` 表可列全表，给职业名则列该职业可用法术。
- 角色卡上记着**已知法术**与**法术位**（`法术`、法术位消耗）。施法属性由职业决定，
  派生**法术攻击加值** = 熟练 + 施法属性调整值，**法术豁免 DC** = 8 + 熟练 + 施法属性调整值。
- 法术位分三档：全施法（法师 / 牧师 / 德鲁伊 / 术士 / 吟游诗人）、半施法（圣武士 / 游侠，
  1 级无法术位）、契约魔法（邪术师，邪术师**短休**即回满）。戏法不消耗法术位。
- DM 用 `cast_spell` 结算：法术攻击自动对抗 AC，需豁免的法术自动算 DC 并掷目标豁免
  （成功按规则减半或免伤），治疗 / 临时生命自动结算，法术位由系统扣；**法术位不够会被打回**。
  不指定环阶时自动用最低可用法术位，也可以显式升环。卡上没有的法术仍可施展，
  但会给 DM 一条「请自行解释来源」的提示；伤害 / 攻击类法术必须先 `start_combat`。
- DM 用 `rest` 处理休息：长休回满生命与法术位（倒地的人也会醒过来、死亡豁免清零），短休只回契约法术位。

落盘位置（`data/plugins/跑团/`）：

- `world/` 全局共享世界库（**多世界**）：`worlds.json` 世界注册表（名称 / 一句话简介 / 主题），
  `worlds/<世界键>/` 每个世界一份（`index.json` 索引 + `docs/<种类>/<名字>.md`，
  种类：世界 / 剧情 / 区域 / 城镇 / 地点 / 地下城 / 场景）；同一世界里的多个故事是
  `docs/story/` 下的多份文档（各带名称与一句话简介）；
- `saves/<存档ID>/` 一份存档（`save.json`（含引用的世界键 `world_key` 与故事键 `story_key`）、角色卡副本 `characters/<user_id>.json`、事件日志 `events.jsonl`、本局场景副本 `scenes/<名字>.md`、本轮等待名单与已提交行动 `round.json`（含倒地 / 阵亡标注）、战斗状态 `combat.json`（先攻 / 当前回合 / 行动经济记账 / 自动结算提示）、出场过的具名 NPC 名单 `npcs.json`、给人看的剧情流水 `story.md`）；`save.json` 的 `progress` 里还记着本局用量（`billing`）、归属会话（`chat_key`）、创建者（`creator_id`）与暂停标记（`paused`）；
- `saves/bindings.json` 会话（群 / 私聊）与存档的绑定；
- `cards/` 角色卡源文件。**DM 的改动只改存档里的副本，不动源卡。**
